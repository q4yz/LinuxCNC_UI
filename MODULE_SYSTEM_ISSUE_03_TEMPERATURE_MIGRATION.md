# Issue #3 — Migrate `temperature` into the module system

> **Status:** not started
> **Tracks:** [`MODULE_SYSTEM_ROADMAP.md`](MODULE_SYSTEM_ROADMAP.md) Phase 3
> **Companion:** [`MODULE_SYSTEM_EVALUATION.md`](MODULE_SYSTEM_EVALUATION.md) § 3
> **Scope:** the temperature feature — backend endpoint, mock-touching
> helper, frontend panel + chart polling loop.
> **Risk class:** medium — see § 3 of the evaluation.
> **Depends on:** Issue #02 (camera) — establishes the migration
> pattern and the lazy-import pattern in the dashboard.

---

## 1. Problem

The temperature feature is currently fragmented:

- `backend/routers/machine.py` hosts the `POST /temperature` endpoint
  (alongside machine-state endpoints that will move to the machine
  module).
- `backend/hardware/linuxcnc_mock.py` owns the simulation loop and
  the `command.set_temperature(...)` mock method.
- `backend/routers/websocket.py` broadcasts the `temperatures` dict
  every 100 ms.
- `frontend/src/components/TemperaturePanel.vue` renders the UI.
- `frontend/src/stores/machine.js` owns the `temperatureHistory`
  rolling 10-second window **and** the 1-second polling interval that
  populates it.

The simulation itself is a process-wide concern (it mutates
`SharedMachineState.temperatures` regardless of who is listening), so
the simulation stays in the mock. Everything else moves.

---

## 2. Goals

1. Move the temperature HTTP surface into `backend/modules/temperature/`.
2. Move the temperature UI + chart state into
   `frontend/src/modules/temperature/`.
3. Move the `temperatureHistory` rolling window + 1-second polling
   interval from `stores/machine.js` into the temperature module's
   Pinia store.
4. Replace `MachineStateService.setTargetTemperature` with
   `ModuleTemperatureService.setTarget` (generated by the OpenAPI
   generator under the new tag).
5. Validate the nullable-module guarantee for temperature.

---

## 3. Non-Goals

- The mock simulation (stays in `backend/hardware/linuxcnc_mock.py`).
- The WebSocket telemetry refactor (Phase 4) — for now, telemetry
  continues to include `temperatures` in the full_state payload.
- Form-from-schema settings UI (Phase 5).
- Removing the legacy single-sensor compat fields (`target_temp`,
  `actual_temp`).
- Real-thermistor hardware backends.

- [ ] Create `frontend/src/modules/temperature/store.js`:

      ```js
      import { defineStore } from "pinia";

      const DEFAULT_WINDOW_MS = 10000;
      const DEFAULT_POLL_MS = 1000;

      export const useTemperatureStore = defineStore(
        "module_temperature",
        () => {
          // state
          const sensors = ref({});               // { extruder: { actual, target }, ... }
          const history = ref([]);               // [{ time, sensors }]
          let pollHandle = null;

          // actions
          function ingest(websocketPayload) {
            // Called by the machine module's WebSocket subscription
            // via the event bus topic 'state.temperatures'.
            if (websocketPayload?.temperatures) {
              sensors.value = deepFreeze(websocketPayload.temperatures);
            }
          }

          function snapshot(windowMs, pollMs) {
            // Polling-loop snapshot into history (zero-order hold).
            const now = Date.now();
            const label = new Date(now).toLocaleTimeString();
            history.value.push({ timestamp: now, time: label, sensors: JSON.parse(JSON.stringify(sensors.value)) });
            const cutoff = now - (windowMs ?? DEFAULT_WINDOW_MS);
            history.value = history.value.filter(p => p.timestamp >= cutoff);
          }

          function start(windowMs, pollMs) {
            stop();
            pollHandle = setInterval(() => snapshot(windowMs, pollMs), pollMs ?? DEFAULT_POLL_MS);
          }

          function stop() {
            if (pollHandle) clearInterval(pollHandle);
            pollHandle = null;
          }

          return { sensors, history, ingest, start, stop };
        }
      );
      ```

## 5. Acceptance Criteria

A CI run on a clean checkout must demonstrate **all five**:

1. `start_dev.sh` boots with `MODULES_ENABLED` empty. Backend logs
   `registry: mounted=['camera','temperature']` (or whatever the order
   is). The dashboard shows the temperature panel with live values
   and the chart populates every 1 s.
2. `curl http://localhost:8000/api/v1/modules/temperature/sensors`
   returns the current sensors dictionary (3 entries by default:
   `extruder`, `bed`, `cpu`).
3. `curl -X PUT -d '{"history_window_seconds": 30}'` to
   `/api/v1/modules/temperature/settings` persists and survives a
   backend restart. The frontend reads the new value on reload and
   the chart shows a 30-second window.
4. Remove `backend/modules/temperature/` and
   `frontend/src/modules/temperature/`, re-run `start_dev.sh`, and
   visit `/settings`. Backend boots with the remaining modules
   (`['camera']`); the dashboard no longer renders the temperature
   panel; no error logs.
5. `npm run build` succeeds with both folders deleted.

## 6. Risks

1. **Single-sensor compat fields leak.** Until `DebugPanel.vue` and
   other legacy consumers are migrated, the WebSocket must keep
   emitting `target_temp` and `actual_temp` (already in the
   `websocket.py` payload). The mitigation is the `ingest` pass-through
   in the legacy `stores/machine.js`.
2. **Mock simulation thread outlives the module.** Per § 3.6 of the
   evaluation, `_temp_simulation_loop()` stays in the mock and runs
   forever once started. Acceptable for v1. Documented in the
   module README.
3. **Pinia store ID collision.** The legacy `useMachineStore` uses
   `defineStore('machine', ...)`. The new temperature store uses
   `defineStore('module_temperature', ...)` — no collision today.
4. **The chart's 1 Hz polling loop is now in two places.** If a future
   developer forgets to call `stop()` on unmount, polling continues
   forever. Add a `defineStore` setup-store `onScopeDispose` hook to
   stop polling when the store goes out of scope.
5. **`temperatureHistory` chart X-axis drift.** Today's loop uses
   `Date.now()` per push; after migration it should derive from the
   poll cadence + `history_poll_interval_ms`. Behaviour should match
   pixel-for-pixel; spot-check during manual verification.
