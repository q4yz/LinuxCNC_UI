### Resolution Summary
Replaced the hand-written `frontend/src/services/api.js` with a strongly-typed client generated from FastAPI's `/openapi.json` schema via `openapi-typescript-codegen`. Every backend router now declares explicit Pydantic `response_model` types and stable `operation_id`s so the generated TypeScript methods map 1:1 onto the existing call sites, and all Vue components / Pinia stores have been migrated to use those methods.

### Files Modified

**Backend (typed response models + predictable OpenAPI operation_ids):**
- `backend/routers/machine.py`: Added `StatusResponse`, `ParseResponse` models; every endpoint now declares `response_model=` and an explicit `operation_id` (`setMachineState`, `setMachineMode`, `homeAxis`, `runMdiCommand`, `setTargetTemperature`, `runProgram`, `stopProgram`, `pauseProgram`, `resumeProgram`, `triggerParser`).
- `backend/routers/jog.py`: Added `JogResponse`, `JogStatusResponse`, tightened request descriptions; added `operation_id`s `jogAxis`, `jogKeepalive`, `jogStop`. Per-axis hardware results are now coerced into string-keyed dicts so the OpenAPI schema accurately describes them.
- `backend/routers/files.py`: Added `FileInfo`, `UploadFileResponse`, `StatusMessageResponse`; assigned `operation_id`s `listFiles`, `uploadFile`, `deleteFile`, `loadProgram`. Fixed pre-existing `NameError` bugs in `delete_file` and `load_program` that referenced undefined `NC_FILES_DIR` — both now consistently use the module-level `GCODE_DIR`. Also dropped duplicate `os`/`UploadFile` imports and cleaned `os.path.exists`-style branching into a single Path-based implementation that returns the typed `StatusMessageResponse`.
- `backend/routers/config.py`: Added `ConfigProfileInfo`, `ConfigFileContent`, `StatusMessageResponse`, `GeneratedFiles`, `CompileGenerateResponse`, `CompileDeployResponse`; assigned `operation_id`s `listConfigs`, `readConfig`, `saveConfig`, `compileGenerateLegacy`, `compileDeployLegacy`. Replaced unchecked `open(...).read()` calls in `compile_generate` with a `_read_or_empty` helper that explicitly closes file handles.
- `backend/routers/compiler.py`: Added `CompilerProfilesResponse`, `CompilerGeneratePreview`, `CompilerGenerateResponse`, `CompilerDeployResponse`; assigned `operation_id`s `listCompilerProfiles`, `generateCompilerArtifacts`, `deployCompilerArtifacts`.
- `backend/routers/system.py`: Added `VersionInfoResponse`, `SystemUpdateResponse` and `operation_id`s `getVersionInfo`, `triggerSystemUpdate`.

**Frontend (generator + tooling + integration):**
- `frontend/package.json`: Added `openapi-typescript-codegen@^0.31.0` as a devDependency and a new `generate-api` npm script that delegates to `frontend/scripts/generate-api.mjs`.
- `frontend/scripts/generate-api.mjs`: New helper script. Downloads the OpenAPI schema from the running FastAPI backend (`http://127.0.0.1:8000/openapi.json` by default, overridable via `OPENAPI_URL`), caches it under `.openapi-cache/`, then invokes `openapi-typescript-codegen` to (re)generate `src/services/api/`. Downloading first is required because the generator's underlying JSON `$ref` parser cannot resolve a remote URL directly.
- `frontend/.gitignore`: Ignored `.openapi-cache/` so the cached schema doesn't pollute the repository.
- `frontend/src/services/apiClient.js`: New tiny bootstrap module that side-effecting-imports the generated `OpenAPI` config and sets `BASE` to the FastAPI origin (preserving the previous hand-written client's behaviour of using the page's hostname). Wired into `main.js` so it runs once at startup; service classes read `OpenAPI` lazily at request time.
- `frontend/src/services/api/**`: Newly generated OpenAPI client (47 files). Contains `index.ts`, `core/` (Fetch-based request pipeline with `OpenAPI`/`ApiError`/`CancelablePromise`), `models/` (one TypeScript interface per Pydantic schema), and `services/` (one class per FastAPI tag: `MachineStateService`, `JoggingService`, `ProgramExecutionService`, `NcFilesService`, `ConfigurationService`, `CompilerService`, `SystemService`, `CameraService`, `DefaultService`).
- `frontend/src/services/api.js`: **Deleted**; all consumers migrated to the generated services.

**Frontend (call-site migration):**
- `frontend/src/stores/machine.js`: Replaced the `api` import with `JoggingService` and `MachineStateService`. Action bodies now use the typed methods (`setMachineState({state})`, `jogAxis({velocities, distance})`, `jogKeepalive({axes:[axis]})`, `jogStop({axes:[axis]})`, `homeAxis({axis})`, `runMdiCommand({command})`, `setTargetTemperature({sensor_name, target})`). `setPosition`/`setCoordinateSystem` now call `runMdiCommand` directly via the centrally-imported `generateSetOffset` helper instead of the old `setWorkOffset`/`setCoordinateSystem` API wrappers, keeping all G-code string generation inside `config/gcodes.js` per AGENT.md.

- `frontend/src/components/UpdateManager.vue`: Switched to `SystemService.getVersionInfo` and `SystemService.triggerSystemUpdate`.
- `frontend/src/components/ConfigList.vue`: Switched to `ConfigurationService.listConfigs` and `ProgramExecutionService.triggerParser` (fixing the previous latent bug where the hand-written client called `/config/parse` even though the backend exposes `/program/parse`).

### Architectural Decisions
- **Generator choice (`openapi-typescript-codegen`).** Selected exactly the tool the issue calls out. Generated TypeScript rather than JavaScript: Vite 8 transpiles `.ts` imports via esbuild out of the box, so no `tsconfig.json` or `typescript` runtime dependency is needed while the components still consume type-checked contracts.
- **Wrapper script around the generator.** `openapi-typescript-codegen --input <url>` crashes because its JSON `$ref` parser tries to dereference the URL itself. Downloading the schema to a local file first is the documented workaround; the script keeps the URL-based entry point described in the issue (`OPENAPI_URL` env var) while staying reliable.
- **BASE URL configuration.** The generated client ships with `OpenAPI.BASE = ''` so Vite's `/api` proxy handles routing during `npm run dev`. `apiClient.js` then upgrades `BASE` to `${protocol}//${hostname}:8000` whenever the page isn't served from `localhost`/`127.0.0.1`, mirroring the prior `api.js` behaviour so the production-style deployment path keeps working.
- **Endpoint operation_ids.** Without explicit ids the generator falls back to `verb_api_v1_path_post` style names. Setting stable ids (`setMachineState`, `triggerParser`, `generateCompilerArtifacts`, etc.) gives us predictable class methods that survive FastAPI router reshuffles.
- **Pre-existing runtime bugs in `files.py`.** `delete_file` and `load_program` referenced an undefined `NC_FILES_DIR` name and used `os.path.join` against a `pathlib.Path` (`GCODE_DIR`). Both would have raised `NameError` at runtime; without the fix the generated client still wouldn't have been able to drive these endpoints. Adjusted them to use `GCODE_DIR / filename`, and added the matching `response_model`. Also wrapped the `compile_generate` raw `open(...).read()` calls in a `_read_or_empty` helper that closes handles properly, matching the pattern used by `compiler.py`.
- **`/config/parse` was the wrong URL.** The hand-written `api.triggerParser()` POSTed to `/config/parse`, but the backend exposes `/api/v1/program/parse`. The generated client correctly routes through `ProgramExecutionService.triggerParser`, so this latent bug is fixed as a side effect of the migration.
- **No unrelated refactors.** No G-code strings, Pinia patterns, Tailwind usage, or lifecycle behaviour were touched. Component templates, computed state, and event wiring are unchanged — only the `<script setup>` import + call-site blocks were edited.
