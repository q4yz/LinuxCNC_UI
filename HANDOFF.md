### Resolution Summary

Added a new Tools module (backend + frontend) that lets operators drive spindles and extruders through MDI commands. The backend exposes ``POST /api/v1/modules/tools/{spindle,extruder}`` via the canonical module-registry pattern, the frontend ships a Pinia store (id ``module_tools``) with a hard-coded mock tool list, and the dashboard renders a new ``ToolPanel`` that switches between a spindle and an extruder UI per the tool's ``type``.

### Files Modified

- `backend/modules/tools/__init__.py` — *new* — package re-exporting ``setup`` for the module registry (mirrors the camera/temperature ``__init__`` shapes).
- `backend/modules/tools/module.py` — *new* — ``ToolsModule`` class with class-level ``ModuleManifest(id="tools", title="Tools", sidebar=None, settings_panel=False)``, an idempotent ``on_unload`` no-op, and ``get_settings_model`` returning ``None`` until the dynamic-config work lands. Module's router field is the module-level ``router`` instance; the registry mounts it under ``/api/v1/modules/tools`` with the ``modules:tools`` OpenAPI tag.
- `backend/modules/tools/router.py` — *new* — ``APIRouter(tags=["modules:tools"])`` exposing two endpoints with ``summary`` + ``description`` metadata and ``operation_id`` strings: ``POST /spindle`` (accepts ``{tool_id, action, speed}``, validates ``action`` ∈ {forward, backward, stop}, emits ``M3 S{speed}`` / ``M4 S{speed}`` / ``M5`` via ``execute_sync_cmd("mdi", 0, …)`` after a blocking ``execute_sync_cmd("mode", 5, MODE_MDI)`` preamble) and ``POST /extruder`` (accepts ``{tool_id, action, distance, speed}``, validates ``action`` ∈ {extrude, retract}, flips the sign of ``distance`` for retract and emits ``G91`` → ``G1 E{dist} F{speed}`` → ``G90``). Pydantic ``BaseModel``s bound to ``Field(ge=…)`` / ``le=…`` / ``min_length=…`` constraints catch malformed payloads with ``422``.
- `backend/tests/test_tools_module.py` — *new* — 18 tests mirroring the temperature-module suite: router mounting, M3/M4/M5 dispatch, ``G91`` + ``G1`` + ``G90`` emission, retract sign inversion, action rejection (400), speed / distance validators (422), factory + lifecycle contract.
- `frontend/src/modules/tools/manifest.js` — *new* — ``FrontendModuleManifest`` with ``id="tools"``, ``title="Tools"``, no sidebar (panel lives in the dashboard), ``settingsPanel: false``.
- `frontend/src/modules/tools/index.js` — *new* — default export with ``manifest`` / ``onLoad`` (no-op) / ``onUnload`` (no-op); lazy store init is triggered by ``ToolPanel.vue`` calling ``useToolStore()`` for the first time, dodging the ``activePinia`` boot-timing race documented in ``MODULE_SYSTEM_ROADMAP.md`` § 12 Gotcha #1.
- `frontend/src/modules/tools/toolStore.js` — *new* — Pinia store id ``module_tools`` constructed via the ``module_${manifest.id}`` template (passes the store-id lint). Seeds a mock array with one spindle (``actual_rpm``, ``target_rpm``, ``set_speed``) and one extruder (``set_speed``, ``distance_index``). Exposes ``sendSpindleCommand(toolId, action, speed)`` and ``sendExtruderCommand(toolId, action, distance, speed)``; both POST to ``/api/v1/modules/tools/{spindle,extruder}``, optimistically update ``target_rpm`` on the spindle, and route errors through ``useConsoleStore().error()`` (instantiated inside the action per ``AI_INSTRUCTIONS.md`` § 21).
- `frontend/src/modules/tools/components/ToolPanel.vue` — *new* — Vue 3 ``<script setup>`` component that iterates ``toolStore.tools`` and renders per-``type`` cards: spindle shows Actual / Target RPM read-only boxes, a Set Speed input, and Reverse / Stop / Forward buttons (Stop styled red, Forward styled green); extruder shows a Speed input, Retract (↑) / Extrude (↓) buttons, and a logarithmic distance slider mapped to ``[0.1, 1, 10, 50, 100]`` with the current mm value displayed above. Click handlers delegate to the store actions; all input controls use Tailwind utility classes (no scoped CSS except the number-input spinner hide).
- `frontend/src/views/DashboardView.vue` — added a nullable ``ToolPanel = panelFor('tools', 'ToolPanel')`` import, a ``toolsMounted = computed(() => registry.modules.has('tools'))`` flag, and a ``<ToolPanel v-if="toolsMounted" />`` slot between the Temperature and Jog panels. Removing the entire ``frontend/src/modules/tools/`` folder falls back to the existing nullable-module contract (panel resolves to ``null``; ``v-if`` skips render).
- `frontend/tests/test-tools-module.mjs` — *new* — 8 source-level tests verifying file presence, manifest shape, ``index.js`` default + named exports, the ``module_${manifest.id}`` store-id template, the mock tool seed shape (spindle + extruder fields), the documented endpoint URLs, the panel's per-type UI blocks + logarithmic distance array, and the dashboard's ``panelFor`` wiring.

### Architectural Decisions

- **New module, not a sibling to ``machine``.** Issue #64 explicitly calls for a "new Tool Module" — the project's module-per-feature convention puts that in ``backend/modules/tools/`` and ``frontend/src/modules/tools/``, matching how ``camera`` and ``temperature`` were split out. ``machine`` continues to own state / mode / home / mdi / jog and now references the tools module only through the URL surface.
- **Hardware access via ``execute_sync_cmd``, not ``linuxcnc.command()`` directly.** ``.agent/AGENT.md`` § 14 forbids importing the real ``linuxcnc`` module in feature code so the backend stays compatible with ``hardware/linuxcnc_mock.py``. Both endpoints route through ``execute_sync_cmd("mode", 5, MODE_MDI)`` for the blocking preamble and ``execute_sync_cmd("mdi", 0, cmd)`` for the fire-and-forget command, mirroring ``backend/modules/machine/router.py::run_mdi``.
- **Mock tool list lives in the frontend store, not the backend.** The issue says "the dynamic config implementation will come later, hardcode a mock ``tools`` array for now". Keeping the seed in ``toolStore.js`` avoids a needless backend GET endpoint until the dynamic config schema lands. The store's ``tools`` ref is already the right shape to swap in a future ``fetch('/api/v1/modules/tools/config')`` call without touching the panel.
- **Sign inversion lives on the backend, not the panel.** The extruder endpoint flips the ``distance`` sign for retract so the front-end never has to remember the convention. Issue #64 § 1 explicitly asks for this.
- **Module store id is ``module_tools``.** The example in the issue uses ``defineStore('tools', …)``; that would collide with the legacy console / machine top-level stores per ``MODULE_SYSTEM_ROADMAP.md`` § 12 Gotcha #2. The actual store follows the lint-friendly ``module_${manifest.id}`` template that the camera / temperature stores already use, and the lint script passes.
- **No settings.py / typed defaults.** Issue #64 ships without a typed schema (``get_settings_model`` returns ``None``). The registry still mounts the four canonical settings endpoints under ``/api/v1/modules/tools/settings``; they return an empty dict today and the front-end treats them as untyped JSON, exactly as documented in ``.agent/contracts/backend-module.md`` § 7.
- **ToolPanel placed between Temperature and Jog in the left dashboard column.** It groups with the other operator-feedback cards (Temperature) rather than the motion-control card (Jog), and sits above the Jog panel so a quick spindle-speed tweak doesn't require scrolling past the jog buttons.
